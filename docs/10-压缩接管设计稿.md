# 10 压缩接管设计稿（换服务路线）

> 状态：**未实现**。本文只讲「怎么把 dsh 的自动压缩换掉」，交付形态见 `09`（作为本插件的 `kind=compaction` 子模块）。
> 结论：走 **① 换服务**（注册自己的 `CompactionEngine`），②配置禁用原生是它的前置，③改 dsh 源码**不采纳**。

## 一、三条路线与取舍

| 档 | 做法 | 能否按 session 拿窗口 | 代价 | 结论 |
|---|---|---|---|---|
| **① 换服务** | 写 `CompactionEngine` 子类注册为 `ctx.compaction`，并禁用原生 `compaction-basic` | **能**（入参是 `agent`，有 `session`） | 要实现触发/摘要/事件/锁（一个子系统） | **采纳** |
| ② 配置禁原生 | bundle patch `auto:false` + 结构化覆盖 preset 内层行 | —— | 只禁不管 | 作为 ① 的前置步骤 |
| ③ 改 dsh 源码 | patch `routedTarget(session)` 或给 adapter 加 session 参数 | 能 | 升级即被覆盖，要维护补丁管理器 | **不采纳**：①已能解决，不值得背 fork |

关键事实：`ctx.compaction` 是 dsh 明确定义的抽象服务（`packages/compaction/compaction/lib/index.js`：
「Implementations own trigger policy, retention, and summarization … Load one implementation per context as `ctx.compaction`」）。
换掉它之后，申报值给多大都不重要——**压不压由我们说了算**。

## 二、为什么 ① 能解决「按会话」

```
我们的引擎.compactNow(agent, …)   →  agent.session.id
                                  →  GET /_team/session/:id/target   （本插件已有）
                                  →  真实模型 → 真实窗口（群配置 / 探测缓存）
```

原生压缩做不到这一步，是因为它只调 `llm.resolveModelInfo(provider, model)`（无 session）。①绕开的正是这一处。

## 三、边界（不做什么）

- **只负责「何时压」**：压力测量直接用 `ctx.tokenMeter.measure(session)`（dsh 自带），阈值自己定
- **摘要沿用 dsh 语义**：把选中区间的消息压成一条摘要节点，不改会话格式、不引入外部存储
- **不碰路由**：virtual model 注册、session→真实模型映射仍由本插件主模块负责
- **不改申报值定义**：申报值仍按 `02` §5.4 三级（配置 → 最低 → 兜底），只是它不再决定压缩时机

## 四、前置：禁用原生（缺一不可）

1. 宿主层：bundle patch 给 `compaction-basic` 行 `auto: false`
2. preset 层：web profile 的压缩在 agent preset 内层，按 id 打不到 → 结构化扫描 plugins 树禁用
3. gate 服务：preset `inject` 一个我们提供的服务才注册；我们没起来时让 preset 回落 stock（**否则会话创建会挂**）

细节与三个坑见 `09` §五（来源：ranxianglei/billion-context 的注释）。

## 五、最小实现清单

> **重要修正（读完参考实现后）**：下表里「测量 / 选范围 / 事务锁 / 事件 / compactNow」**都不必自己写**。
> `dsh-live-compact` 的做法是 `class SpineCompactionEngine extends BasicCompactionEngine`，只覆盖
> `compactIfNeeded(agent, trigger, signal)` 与 `summarize(input, agent, signal)`，其余全部继承。
> 所以真实工作量是**一个类 + 两个方法**，不是下面这份清单的全部。

| 组件 | 要做什么 | 注意 |
|---|---|---|
| `class TeamCompaction extends CompactionEngine` | `super(ctx, 'compaction')` | 每 context 只能一个；注册前检测是否已被占用，被占则**放弃并 warn**，不硬抢 |
| `compactNow(agent, signal, commandId)` | 手动压缩入口（`/compact` 命令会调） | 失败抛 `ManualCompactionError`（`busy` 子类用于并发） |
| 自动触发 | `ctx.on('agent/pre-step', …)` 里测量 + 判断 | 与原生同一时机；内部必须快，压缩本身异步 |
| 阈值判断 | `measure(session).tokens / 真实窗口 > 比例` 才压 | **窗口未知 → 不压**（不猜）；比例可配 |
| 摘要调用 | 用该会话的真实模型发一次摘要请求 | 走本插件的 adapter；失败不推进会话，只放弃本次压缩 |
| 事件 | 写 `compaction/start`、替换区间为一条摘要节点，用 `compactCheckpointSource` 标记 | 让消费方能识别、能关联 |
| 事务锁 | 同一 session 不允许并发压缩 | 复用 dsh 的 durable lock 语义，冲突报 `busy` |
| 保护 | 摘要期间 surface 变了 → 放弃本次（不写坏历史） | 原生有 `SurfaceChangedError`，我们照此处理 |

## 六、触发流程（伪代码）

```js
on('agent/pre-step', async ({ agent, signal }) => {
  const window = await resolveRealWindowForSession(agent.session.id);  // 本插件提供
  if (!window) return;                        // 未知 → 不压
  const m = ctx.tokenMeter.measure(agent.session);
  if (m.tokens / window <= RATIO) return;      // 未到阈值
  await this.compact(agent, signal);           // 加锁 → 选范围 → 摘要 → 写事件
});
```

## 七、验收标准

1. **不卡启动**：禁用原生并注册我们的引擎后，新建会话正常（不出现 preset 永久等待）
2. **按真实窗口压**：真实模型 128K、申报 1M 时，上下文到 ~128K 触发压缩，而不是等到 1M
3. **未知不压**：查不到真实窗口时不压缩、不报错，只是不干预
4. **能退**：引擎初始化失败/被禁用时，宿主回落 stock 压缩，会话仍然可用

## 七点五、参考实现：dsh-live-compact 1.0.1（已实读源码）

仓库 `MerkyorLynn/dsh-live-compact`（零依赖、679 行）。它的做法与本设计稿原估算**不同且更省**：

| 它的做法 | 出处 | 对我们的含义 |
|---|---|---|
| bundle patch 里 `compaction-basic: disabled: true` + `insert: compaction-spine` | `cordis.patch.yml` | 与我们 §四「两层禁用」一致，但 patch 直接 insert 新行，比结构化扫描更简洁（非 web profile 够用） |
| `class SpineCompactionEngine extends BasicCompactionEngine` | `index.js:131` | **继承而非重写**：测量/选范围/锁/事件/`compactNow` 全部免费 |
| 只覆盖 `compactIfNeeded(agent, trigger, signal)` 与 `summarize(...)` | `index.js:283`、`index.js:291` | 需要自己写的就这两个方法 |
| 阈值 `SPINE_MIN_TOKENS` 默认 **20000**，远低于 dsh 的 80% | `index.js:22` | 「边做边压」：不等堆满，切刚结束的那一轮 |
| 摘要**不调模型**：原文 shadow 落盘，会话里只留「卡片 + 文件指针」 | `index.js:300-305` | 压缩成本从「十几秒 + 计费」降到毫秒级；代价是不能靠模型做语义摘要 |
| 卡片靠启发式抽取（代码行/路径/表/义务/报错行/研究符号） | `plan.js` 的 `CODE`/`PATH`/`OBLIGATION`/`ERROR_LINE` 等正则 | 质量取决于启发式覆盖，不是理解 |
| 大压缩兜底 `BIG_GATE = 650000`，`URGENT_TOKENS = 48000` | `index.js:19-21` | 「雷霆大压缩能拖就拖」，拖到实在不行才让模型摘要上场 |

**它的实测（README 里两场，均为长链路任务）**：

| | 原版 | 插件 |
|---|---|---|
| 全程采样命中率 | 99.55% | 99.56% |
| 20 题场景：题末平均上下文 | 366,942 | **217,276（低 40.8%）** |
| 20 题场景：结束上下文 | 433,844 | **323,726（低 25.4%）** |
| 大压缩耗时 | 14.552 秒（第 15 题触发） | 20 刀共 **74 毫秒** |
| 采样命中率（20 题） | 99.87% | 99.90% |

> 注：这些都是对方自述数据；「墙钟 6,105 秒」那场他们自己也说明「只跑了插件一边，快出来的时间不能全算在插件上」。

**结论**：如果要做压缩接管，第一版应当**照它做**（继承 + 本地卡片 + 高门槛兜底），而不是按本稿原先的「重写引擎」路线。

## 八、风险

| 风险 | 处置 |
|---|---|
| 双压互毁（没禁干净） | 启动自检：检测到原生 `compaction-basic` 仍加载 → 报错并**主动不接管** |
| gate 没提供 → preset 卡住 | 必须实现回落分支；没把握就保持 stock |
| 摘要模型循环依赖（用坏模型摘要好模型） | 摘要固定走该会话的真实模型；模型不可用时放弃本次压缩，不阻塞发送 |

## 九、与「项目停工」的关系

本文只是路标：现在**没做**，默认行为仍是原生压缩 + 三级申报（`02` §5.4、`07` §二点六）。
要做的时候，按 §四 → §五 顺序推进，先让 ② 单独跑通（验证「没有原生压缩也能正常开会话」），再接 ①。
