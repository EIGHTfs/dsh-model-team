## 一、界面组成

界面分三层，从"最小入口"到"完整界面"：

```
悬浮球（收起态：球 + 当前目标徽标）
  └ 点击 → 悬浮面板（当前群聊 / 会话 / 目标 / 速率 / 总量 + 进入按钮）
       └ [进入群聊界面] → 主窗口
            ├ 顶栏：团队标识 + 当前视图名 + 收起键（收回成球）
            ├ 内容区：按视图切换（由主题渲染）
            └ 底边栏：消息 / 通讯录 / 我   ← 唯一的视图入口
```

| 约束 | 规定 |
|---|---|
| 入口唯一（INV-13） | 三个视图**只能**从底边栏进入；顶栏与群列表头部不得再放入口按钮 |
| 收回方式 | 顶栏**允许一个收起键**（收回成球，见条款 8）；**不设关闭整窗键** |
| 球的作用 | 球是主入口也是"是否该出现"的判据载体：球隐藏时主窗口一并隐藏（§7.3.6） |
| 面板 | 面板是"轻量查看"，不替代主窗口；它的展开方向与位置由宿主状态决定（§6.1） |

### 技术形态（0.4.0 定稿）

界面由**主题**渲染：一个主题 = 一个 `ui/themes/<id>.tsx`，构建期编译进产物，运行时由宿主容器挂载。

| 项 | 规定 |
|---|---|
| 渲染 | 主题导出的 React 组件树；`react` / `react-dom` 由 DSH 宿主提供，不打包进产物 |
| 样式 | 主题自带，选择器限定在主题根节点下 |
| 构建 | `node build.cjs` → `lib/client.js`；两个主题都必须能单独编译（`theme-compile` 门禁） |
| 预览 | 真实界面需要 DSH 宿主；`scripts/mock-team-server.mjs` 只提供**产物自检页**与假数据接口 |

> 早期"纯静态 HTML + CSS"方案已随 0.4.0 移除（`ui/index.html` 与 `ui/css/**` 已不存在）。

## 二、必需 DOM 钩子（主题必须提供）

> 0.4.0 起界面只有主题：**钩子由主题源码提供**，legacy HTML 的那套钩子已全部下线（门禁按 `ui/themes/*.tsx` 校验）。
> 下线清单与理由见 §2.4。

### 2.1 悬浮球 / 悬浮面板

| 钩子 | 元素 | 说明 |
|---|---|---|
| `#floatBall` | 主题内可点击元素 | 球本体；内含 `[data-fb-target]` 作为**目标指示容器**：渲染接活平台（effectiveTarget 所属群）的头像；无头像时用平台首字母圆牌。**不显示模型名文本**（模型名走 `title`/`aria-label`，避免小球内文字溢出） |
| `#floatPanel` | 容器 | 展开面板 |
| `#fpHead` | 容器 | 面板标题条（拖动抓手） |
| `#fpTitle` | `button` | 标题左侧入口 → 数据库页 |
| `#fpEnter` | `button` | `[ 进入群聊界面 > ]` |

**显隐落点**：宿主容器 `[data-dmt-theme-host]` 上的 `data-dock-visible="true|false"`（见 §7.3.6）。主题用 CSS 响应它，例如
`[data-dmt-theme-host][data-dock-visible="false"] .tim-ball-anchor { display: none }`。

### 2.2 主窗口

| 钩子 | 元素 | 说明 |
|---|---|---|
| `.team-app` | 容器 | 主窗口根（主题自有类名可另起，但必须带此 class）；尺寸由主题 `size` 或 `--team-window-width/height` 控制 |
| `.team-tabbar` | 容器 | 底边栏（`role="tablist"`） |
| `.team-tab[data-view]` | `button` × 3 | `data-view ∈ list/contacts/profile`；选中态 `aria-selected="true"` |

### 2.3 视图内锚点（主题自绘，宿主只读不写）

| 锚点 | 用途 |
|---|---|
| `data-view="list|chat|add|contacts|profile"` | 当前页面容器（主题按页渲染） |
| `data-*` 状态标记 | 各页的空态/加载态，供门禁与验收断言（如 `data-add-state`、`data-contacts-state`、`data-platform-empty`） |

> 视图内具体结构由主题决定，宿主**不得**按 id 抓取视图内部元素来填数据——数据一律经 Bridge（§八）下发。

## 三、状态类与属性（JS 只动这些）

| 类 / 属性 | 语义 | 主题必须做什么 |
|---|---|---|
| `[data-dock-visible="false"]`（在主题宿主容器上） | 悬浮件隐藏 | 主题用 CSS 响应它（隐藏球/面板）；**禁止 JS 直接改 `display`**，也禁止在主题里另存一份显隐状态 |
| `.is-dragging` | 拖动中 | `transition: none; will-change: transform` |
| `[aria-selected="true"]` | 当前 tab | 高亮 |
| `.avatar-img` / `.avatar-fallback` | 头像图 / 文本占位 | 图片加载失败时换下一个候选（回退链见 §10.4.1） |
| `[data-collapsed]` | 面板折叠态 | 对应视觉 |

**禁止**：JS 直接写 `element.style.*` 的尺寸/颜色/圆角——一律由主题 CSS 决定。
唯一允许的内联样式：拖动位移 `transform` 与落位 `left/top`。

## 五、界面条款（逐条可验收）

### 5.1 悬浮球 / 面板

| # | 条款 |
|---|---|
| 1 | 球显示当前目标：单模型显示模型名（过长截断，如 `(glm-5.3-fl…)`）；分组显示 `@分组名`；未设置显示 `—` |
| 2 | 标题栏：左 `👤 我的模型团队`（点击进数据库页）、中 `模型 <目标>`、右 **只有 `—`（收起面板）**。**不设 `×` 关闭整窗，也不设呼出入口**——球的显隐只由 INV-14 决定，用户不手动关球（`×` 与「呼出模型团队」属实现期自加项，不在需求内） |

| # | 条款 |
|---|---|

### 5.3 群列表

**隐喻来源**：群列表仿的是聊天软件的**消息列表**——一条「会话」= 一个平台账号（群）；「最新消息」= 该账号的账号信息（限速 / 限额 / 余额 / 并发等）。各平台字段不同，所以摘要由后端按 **env 模板**渲染成**单行成品字符串**（`02` §3.1 的 `summary`），前端只负责显示、不做拼装。

## 六、交互实现要点（踩过坑的）

| 要点 | 正确做法 | 历史事故 |
|---|---|---|
| 悬浮球开合 | `pointerdown` 只记录 `panelWasOpen`；超 4px 才算拖动并收起；`pointerup` 未移动时按 `panelWasOpen` 决定开/关 | F-01：`pointerdown` 里直接收面板导致"只能开不能关" |
| 渲染后聚焦 | 渲染前记 `document.activeElement`，只有原本就在输入框才恢复；打开主窗口后主动 `blur()` | F-02：每次渲染无条件 focus 搜索框，移动端弹软键盘 |
| 重复挂载 | 检测 `.dmt-host` + `#floatDock` 同时存在就复用，只有孤儿节点才清理重建 | F-03：二次挂载后新 DOM 无监听，切换 session 面板空白 |
| 系统消息 | 只从后端 events 读，前端**不许**本地插入 | F-04：前端插 + 后端存双源，刷新后文案不一致 |
| 多源合并排序 | 先定排序键（`at`，缺失用 `time`）+ 同键规则（rows 在前），再写渲染 | F-05：两段拼接导致每次进入顺序不同 |
| 固定尺寸容器放长文本 | 必须量 `scrollWidth > clientWidth`，用最长可能值测 | F-06：球内文字溢出球体 |

### 6.1 悬浮件状态与位置

悬浮球与悬浮面板的「显隐 / 位置 / 展开方向」只有一处真相源：`ui/js/float/dock-state.js`（状态工厂）。

| 项 | 口径 |
|---|---|
| 显隐 | 工厂里的 `visible` 是唯一来源；`lib/client-parts/dock.js` 只把 INV-14 判定结果写进工厂（`setDockVisible(decision === 'ours')`），**不留显示副本**；落地方式是主题宿主容器的 `data-dock-visible` 属性 |
| 位置 | 只持久化**收起态锚点** `{left, top}`（球的左上角）；面板位置由「锚点 + 面板尺寸 + 展开方向」算出，**不落盘** |
| 夹取 | `clampDockPosition(left, top, size)`：`min=0`、`max=max(0, 视口-尺寸)` ⇒ **整块留在视口内**；球用球尺寸、面板用面板尺寸，各按当前形态夹 |
| 展开方向 | `computeOpenDir()`：锚点中心相对视口中心决定象限（`openLeft = cx ≥ vw/2`、`openUp = cy ≥ vh/2`），由宿主写到主题宿主容器的 `data-open-dir`；球靠右→文本在左、靠左→文本在右（永远朝视口内侧）。拖动松手与 resize 后重算 |
| 动效 | 只过渡尺寸/透明度/位移（`width 220ms cubic-bezier(.16,1,.3,1)`、`opacity 180ms`、`transform 220ms`）；`left/top` **不参与过渡**，否则拖拽会发飘 |
| 旧键迁移 | 历史键 `dsh-model-team:anchor` 在工厂加载时迁移进 `dsh-model-team:dock-state-v2` 并删除旧键，避免两份真相并存 |


## 七、主题（TSX）

**一句话**：主题只声明「控件、大小、样式、内部动作」；数据与对外动作由宿主提供。主题不联网、不碰存储、不直接调 `/_team`。

### 7.1 形态与构建

| 项 | 规定 |
|---|---|
| 一个主题 | **一个主题 = 一个 `.tsx` 文件**（如 `ui/themes/tim.tsx`、`ui/themes/classic.tsx`）；可并存多套，运行期切换 |
| 构建 | TSX 在**构建期**编译成 CJS bundle，内联进 `lib/client.js` 的 `ModuleLoader` 工厂；运行期不加载裸 ESM |
| 依赖 | `react` / `react/jsx-runtime` / `react-dom` **由 DSH 宿主提供**（18.3.1），主题产物只留 `require` 字面量、不打包 react；构建期工具放 `devDependencies`，**使用 DSH 已有依赖不算破零依赖** |
| 样式 | 主题自带样式（内联或随 bundle），不得全局污染宿主：所有选择器限定在主题根节点下 |
| 目录 | 前端目录沿用 **`ui/js`**（不引入 `host/` 之类的新层）；主题文件放 `ui/themes` |

### 7.1.1 默认主题

| 项 | 规定 |
|---|---|
| 默认主题 | **`tim.tsx`**：未配置主题时使用它 |
| 备选主题 | **`classic.tsx`**：保留、可在配置里切换，不再是默认 |
| 切换方式 | 配置项指定主题 `id`（与文件名一致）；指向不存在的主题 → 构建失败并带出路径，不静默回落 |

### 7.2 主题声明形状

主题默认导出一个声明对象，宿主只认这些字段：

| 字段 | 必填 | 说明 |
|---|---|---|
| `id` | 是 | 主题标识（与文件名一致），用于配置与切换 |
| `name` | 是 | 展示名 |
| `size` | 否 | 主窗口尺寸覆盖（`width` / `height`，CSS 长度字符串）；缺省用本文档条款 10 的默认值 |
| `styles` | 否 | 该主题的样式表（字符串或列表） |
| `render` | 是 | 渲染函数：接收宿主注入的 `bridge`，返回界面 |
| `actions` | 否 | 主题内部动作（如「记住上次 tab」这类纯视觉状态操作），不参与宿主数据 |

**主题本地状态归主题**（当前 tab、@ 浮层开合、请求卡片展开态、输入框草稿）；**跨页面或需持久化的归宿主**（当前群、当前目标、悬浮件锚点与开合）。

### 7.3 主题能做什么 / 不能做什么

| 能做 | 不能做 |
|---|---|
| 决定控件长什么样、用什么控件、尺寸与样式 | 自己 `fetch` / 读 `localStorage` / 直接调 `/_team` |
| 组合宿主给的组件与数据 | 改宿主 store 的内部字段、注册新端点 |
| 主题内部纯视觉状态 | 伪造业务数据（缺数据显示空态，不许编造） |
| 覆盖窗口尺寸、颜色、圆角、字号 | 全局改写宿主页面样式（含 `body`、宿主浮层） |

### 7.3.5 投影入口（适配层，唯一入口）

主题与业务代码**不得**直接读宿主内部对象（如 `session.projections.faceOf(...)`）。取值与订阅统一经适配层：

```
ui/js/interaction/model-selection-source.js
  resolveModelSelectionSource(props) → { getSnapshot(), subscribe(cb) } | null
```

| 要求 | 说明 |
|---|---|
| 通道优先级 | 按信息量从高到低探测（hook → 对象投影 → 直接 prop → 会话快照 → 无），命中即用 |
| 命中留痕 | 一次性日志 `[selection-source] channel=<name>`；下次升级只需看这一行 |
| 缺失语义 | 返回 `null`，调用方按「判不了」处理；不抛错、不编造 |
| 结论分级 | `拿到值并判定` > `值还没到` > `通道不可用`；低信息量**不得覆盖**高信息量 |
| 版本演进 | 官方换读法时**只改这一个文件**；新增通道只加一行探测 |

> 判据：全仓 `grep "projections.faceOf"` 只允许命中适配层文件。

### 7.3.6 主窗口与球的显隐关系（单向）

| 规则 | 说明 |
|---|---|
| 球隐藏 ⇒ 主窗口隐藏 | 判定为「不该显示」时，主窗口必须随之隐藏（判据透传），不得残留窗口 |
| 球显示 ⇏ 主窗口显示 | 反过来不成立：球可见时主窗口仍按用户意图（未展开/已收起）决定，**不自动弹出** |
| 为什么单向 | 打开宿主页面时，若当前会话不是我们的虚拟模型，用户不该被聊天界面糊一脸；而用户在用时，窗口是否展开应由用户控制 |
| 收起键与判定叠加 | 用户点「—」收起 → 球仍在（判定为 ours 时）→ 点球展开；判定转为非 ours → 球隐藏且窗口一并隐藏 |

### 7.4 与宿主的边界

- **宿主提供**：数据（见 §八）、动作（见 §八）、悬浮件状态、会话与目标解析。
- **主题提供**：视图结构 + 样式 + 本地视觉状态。
- **悬浮球/悬浮面板**：由主题渲染（视觉），**状态与几何**（显隐、锚点、展开方向、命中判定）由宿主维护；**主题不得自己持久化 dock 状态**（不写 `localStorage`、不在主题内维护 `visible`/`left`/`top` 副本）。
- **禁用项（硬）**：主题内出现 `fetch(`、`localStorage`、`/_team`、`window.__` 直接访问即视为越界，构建门禁会红。

### 7.5 切换与兼容

| 场景 | 规定 |
|---|---|
| 缺省主题 | 未配置时用内置默认主题；配置指向不存在的主题 → 构建失败并带出路径，不静默回落 |
| 切换主题 | 运行期切换不得重建宿主页面；切换后宿主关键状态（当前会话、目标、群列表）必须保持不变 |
| 旧通道 | 旧的「主题 = 一份 HTML 骨架」通道仅作过渡：**删除时机 = tim 主题三页（消息 / 通讯录 / 我）全部补完之后**；过渡期两套可切换，但**不得同时渲染** |

## 十二、门禁（与界面相关的部分）

`node scripts/gate-all.mjs` 共 13 道；与界面/主题直接相关的是这 5 道：

| 门禁 | 校验什么 | 失败说明 |
|---|---|---|
| `build` | 构建产物是当前源码的构建结果；产物含主题 bundle | 产物陈旧或主题没编进去 |
| `theme-compile` | 每个主题都能单独编译；`meta.id` 与文件名一致；产物含主题根；**不含旧式全局隐藏规则** | 模板字符串被截断，或主题把 legacy 隐藏规则加回来了 |
| `contract` | 契约钩子（§二 的 8 个）在主题源码里齐全；端点与路由逐条对应 | 主题缺锚点，或端点表漂移 |
| `ui-contract` | U-3 界面无平台名字面量 / U-7 加群选项投影只有 `id`+`label` / U-8 主题不含值字段名 | 分层被破坏（值混进显示层） |
| `render` | 主题锚点 + 面板字段占位 + 层级 `panel < app`；产物不含 7 个退役渲染符号 | legacy 渲染层想复活 |

另有两道间接相关：`no-local-paths`（文档/注释/代码里禁止绝对路径与本机描述）、`doc-refs`（文档与**代码注释**里的 `docs/NN` 引用必须指向真实存在的文档）。
