# 01 需求与不变量

> 本文件只回答两件事：**这个项目为什么存在**、**哪些事实一旦违反就必须推倒重来**。
> 具体接口字段见 `02-契约.md`；界面条款见 `03-UI规范.md`。本文件不重复它们。

## 一、需求原点

**背景**：DSH 一个平台下挂着多个模型；一个 session 内切换模型**不会**影响其他 session（隔离是 DSH 已有的，不是本项目要解决的问题）。

**真实问题**（按破坏力排）：

1. **模型会永久不可用** —— 下架、额度耗尽、被限流封禁。不是临时抖动，是必须换掉才能继续
2. **子代理（subagent）没有官方的模型切换方法** —— 主 session 可以手动切，子代理只能固定在某个模型上
3. 于是：模型一失效，子代理那条任务链就断在那里，没有自救手段

**解法**：在 DSH 侧只暴露**一个**虚拟模型；真正的模型由插件在每次请求时按「当前 session」查映射决定。

```
DSH 请求（model = 虚拟模型名）
   → 插件 LlmAdapter 拦到（进程内，不过 HTTP）
   → 用 dsh 盖在 options 上的 sessionId 查映射
   → 改写 model 为真实模型
   → 转发上游，流式回传
```

**为什么值得做**：子代理是并行的主要生产力；模型一旦失效，整条任务链断在那里且官方没有恢复手段。这个插件把「换模型」变成**父 session 一次操作就能覆盖子代理**的动作——靠的是 `parent` 回落（父链递归，见 `07-实现要点.md` §二）。

附带价值：不同任务用不同模型（写代码要强模型、闲聊要快模型）不必来回切全局设置。

## 二、产品形态（一句话）

切模型不发生在下拉框里，而发生在**群聊界面**里：
平台账号 = 群、模型 = 群友、发 `@模型名` = 把本 session 目标切到它、请求记录 = 群友消息、我发的 `@` = 右侧气泡。

**「我」是什么**：不是系统角色，而是**当前 dsh 用户**。三条具体含义：

1. **发送者**：聊天流右侧气泡就是「我」发的 `@模型名`（不是灰色系统提示）
2. **收纳库**：群列表（仿消息列表）本质是「我」的账号库——一个平台账号 = 一条会话；「我」的配置（`config.json`）就是这个库的数据源
3. **导入即登录**：批量导入账号配置 = 「我」登录多个平台；这是`POST /_team/import` 的产品语义（区别于「加群」= 添加单个账号）

**入口归属（已定稿）**：讨论期曾计划在群列表顶部放「我」的入口，后续底边栏定出三个 tab（消息 / 通讯录 / 我）后**回收了顶部入口**——同一个页面不允许两个入口（INV-13）。

## 三、不变量（违反任何一条 = 验收不通过）

> 每条都必须**可机器验证**或**可一次命令验证**。标注「门禁」的已写进 `scripts/check-contract.mjs` 或测试用例。

| 编号 | 不变量 | 为什么不可违反 | 怎么验 |
|---|---|---|---|
| INV-01 | DSH 模型列表里本项目只贡献**一个**模型 | 多注册一个就退化成普通多模型插件，核心差异点消失 | `listModels()` 返回长度 = 1（门禁） |
| INV-02 | 切换只影响目标 sessionId 的**后续**请求 | session 间串模型 = 用户在最贵的场景里用到便宜模型 | 两 session 切不同模型，各自下次请求 model 互不串（门禁） |
| INV-03 | 管理端点前缀 `/_team/`；对外入口只有裸路径 `/v1/chat/completions` 与 `/v1/models` | 加前缀 DSH 找不到入口 | 路由表扫描（门禁） |
| INV-04 | `groups/:id` 是平台账号 id，`session/:id` 是 dsh sessionId，两套 id 不互相解释 | 混用会把请求发到错误平台 | 用群 id 请求 `session/:id/*` 必须不命中（门禁） |
| INV-05 | 任一驱动加载或运行失败，网关与其他驱动不受影响 | 一个坏驱动打死整个插件 | 放入故意抛错的驱动 → 网关仍启动、其余可用（门禁） |
| INV-06 | 配置文件缺失 → 自动建空配置并继续；解析失败 → 内存降级并继续 | 新装用户首次启动不能崩 | 删/损坏 config 后启动，进程存活（门禁） |
| INV-07 | 请求记录行字段齐全，缺值一律 `—`，不留空串/`undefined` | 悬浮 title 要还原完整原始日志 | 发一次请求后逐字段断言（门禁） |
| INV-08 | 摘要模板变量缺失时渲染 `—`，不报错、不阻断列表 | 一个平台配置残缺不能拖垮整页 | 配一个引用不存在变量的模板 → 列表正常（门禁） |
| INV-09 | 切换在**消息发送时**生效，只影响下一次请求，不改已发请求 | 时机含糊会导致前后端各写一套 | 切换后同 session 再发一次，model 为新值（门禁） |
| INV-10 | 插件入口**禁止 `export default`** | 有 default 时 `inject`/`name` 被宿主 `||` 吃掉 → `cannot get property "llm" without inject` | import 后断言 `mod.default === undefined`（门禁） |
| INV-11 | 同一事实的**写入字段名与读出字段名**必须各自唯一，且契约里两处都写明 | 历史事故：写 `driverId`、读 `driver`，加群恒 400 | 契约表 + 用例用**契约字段名**构造载荷（门禁） |
| INV-12 | 要持久化的事实只允许**一处写入源**，前端只读不造 | 历史事故：系统消息前端插一条、后端存一条，刷新后文案不一致甚至重复 | 刷新前后序列化比对一致（门禁） |
| INV-13 | 同一功能只允许**一个 UI 入口** | 历史事故：群列表顶部「我」与底边栏「我」两个入口指向同一页 | 入口清单与视图一一对应（门禁） |
| INV-14 | 悬浮球**仅当**当前会话选中的模型是本插件的虚拟模型时可见。判定依赖两个输入：会话的模型选择、插件元信息是否可用。**任一输入在重试后仍不可用，则判定为「不可知」并隐藏** | 用户在看别的模型时不该被无关浮球干扰；「没在用却一直显示」也是误导，判不了时宁可少显示 | 切到其他模型 → 浮球不出现；切回虚拟模型 → 出现且**无需刷新**；切走 → 立即消失；meta 三档重试仍失败 / 宿主无 projection → 隐藏 |

## 四、明确不做的事（防止范围蔓延）

| 不做 | 原因 |
|---|---|
| 不做「反向代理式」多模型网关 | DSH 有进程内 `LlmAdapter` 接缝，走 HTTP 多一跳、还要猜 session，没必要 |
| 不向 dsh 的 session 日志写入 | 写别人的日志等于伪造宿主状态，格式随版本变 |
| 不做 Cookie / 浏览器凭证类接入（`accessMode: 'reverse'`） | 本项目只做官方 API + API Key；字段保留为将来扩展 |
| 不做跨平台统一定价 / 计费 | 各平台口径不同，本插件只如实展示上游返回的 usage |

## 五、术语（避免同物异名）

| 术语 | 含义 | 注意 |
|---|---|---|
| **群** | 一个平台账号（如某平台的某个账号） | 旧称"好友"已废弃，别再用 |
| **群友** | 该群下的一个模型 | |
| **目标（target）** | 某 session 当前指向的模型或分组 | 不是"当前群" |
| **好友分组** | 跨平台同名模型的聚合，按策略轮换/故障转移 | 跨平台，所以**没有唯一归属群** |
| **session** | dsh 的一次对话，以 sessionId 标识 | 由 dsh 盖章，不由本插件生成 |
| **我** | 当前 dsh 用户（操控者）。其「账号」是**所有平台账号的收纳库（数据库）** | 不是系统角色；「我」@模型 = 右侧气泡；导入配置 = 登录账号入库；群列表即「我」的账号库视图 |
