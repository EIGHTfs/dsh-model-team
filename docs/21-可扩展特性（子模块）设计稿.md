# 21 可扩展特性（压缩 / 反代 / 本地网关）设计稿

> 本文件保留扩展接入的能力需求，不表示通用插件发现机制已经实现。
> **所有扩展低耦合**：各插件自己声明能力，model-team 动态发现后按公共契约动态注册；不能把可选功能静态收编成核心子模块。具体边界见 `06`，当前缺口见 `13` §二。
> 压缩引擎的选择由宿主配置管理，不由反代或其他扩展擅自改写。

## 一、可选插件接入边界

| 事项 | 规定 |
|---|---|
| 打包 / 目录 | 插件实现自包含；同仓或独立包不改变低耦合要求 |
| 发现 | model-team 从明确的插件发现来源取得当前声明，不静态 import 某个平台 |
| 注册 | 插件自己声明，model-team 按公共契约动态注册；不可在核心另维护一份名单 |
| 隔离 | 缺失、停用、损坏只影响对应插件；成功、失败、卸载、再挂载均有明确生命周期 |
| 宿主能力 | 通过作用域明确的能力接口注入，不把可选服务变成核心必需依赖 |

不得把“只安装一个包”当作收编可选功能的理由；现有驱动扫描也不能证明完整插件发现机制已完成。

## 二、已有范式：`drivers` 怎么加载（照抄它）

事实（`src/gateway/drivers/index.js`）：扫描 `<dataRoot>/drivers/*.js` → `await import()` → 校验形状
（`id` / `name` / `accessMode` / `authSchema` + 可选 `fetchModels` / `fetchSummary`）→ 注册进驱动清单。

这本身就是一个"子插件"机制，只是**目前只服务驱动**。推广方式：给模块加 `kind` 字段，
加载器按 `kind` 校验不同的形状要求，并把对应的受限 API 注入进去。

```js
// <dataRoot>/extensions/proxy-openai.js 形态示意
export const id = 'proxy-openai';
export const kind = 'proxy';            // 'proxy' | 'gateway' | 'compaction'
export function register(api) {
  api.registerRoute({ method: 'POST', path: '/proxy/:groupId/*', handler });
}
```

## 三、三个扩展点

| kind | 需要注入什么 | 模块要实现 | 硬约束 |
|---|---|---|---|
| `proxy` | `registerRoute({method, path, handler})`、`dataRoot`、`logger`、`config` | 自己拼上游 URL、转发、错误映射 | 路径必须挂在 `/_team/` 或独立前缀下，不能抢占宿主已用路径 |
| `gateway` | 同上 + 现有 `/_team` 语义 | 鉴权、限流、模型别名 | 与 `http.externalOpenAiCompat` 开关一致，默认关 |
| `compaction` | `ctx`（由主插件代注册）、`getSessionTarget(sessionId)`、`dataRoot` | 继承 `CompactionEngine`，实现 `compactNow` 与自动触发 | ①每 context 只能一个实现 ②**必须先在 profile 禁用内置压缩**，否则双压互毁。详细设计见 `22` |

**压缩这条的额外要求**（不能省）：profile 的 `cordis.patch.yml`（或 bundle patch）里把 `compaction-basic`
行关掉。web profile 的内置压缩跑在 agent preset 内层，按 id 打不到时要做结构化匹配——
细节与三个坑见 §五。

## 四、与现有代码的关系（不破坏）

- `drivers` 契约**不动**：仍按原形状加载；`extensions` 是新增目录与新增 `kind`，两者不交叉
- 没有 `extensions/` 目录时行为与现在完全一致（加载器扫不到就跳过，只 warn 一次）
- 每个模块与主插件同受约束：单文件 ≤400 代码行、零第三方依赖、注释只写为什么

## 五、可借鉴的开源实现

**billion-context（压缩）**——三个用事故换来的点：

| 做法 | 为什么 | 我们怎么用 |
|---|---|---|
| bundle patch 给 `compaction-basic` 打 `auto: false` | 宿主层能按 id 命中 | 照抄 |
| 结构化 overlay 扫描 preset 内层 plugins 树 | web profile 的压缩在 preset 内部，按 id 打不到（他们 #1772/#2360） | 照抄，这是最容易漏的一层 |
| 常开的 gate 服务 + 回落 stock | 禁用插件被 kill 时 preset 不会永久卡等待（#3662「把会话创建搞砖了」） | 照抄，gate 必须与压缩模块解耦 |
| 必须真禁用，不能共存 | dsh 的压缩检查点会持久遮住原始历史，两边都压互相毁原料 | 照抄 |

**dsh-providers-hub（扩展组织方式）**——它是**源码级** provider 模块（`src/accio.ts`、`src/astudio.ts`…），
不是运行时插件；值得学的是它的组织纪律：一个 provider 一组文件（adapter/auth/oauth/product），
外加一份 `docs/adding-a-new-provider.md` 说清"加一个要动哪几处"。我们照这个写 `docs/adding-an-extension.md`。

## 六、MVP 顺序（若要做）

1. **proxy**：最小可用 = 把某个群的 `baseURL` 挂到 `/_team/proxy/<groupId>/*`，透传鉴权与错误码
2. **gateway**：在已有 `/v1/chat/completions` 上加鉴权与限流开关
3. **compaction**：最后做（要先解决 profile 禁用内置），只做"按真实模型窗口触发压缩"

## 七、风险

| 风险 | 处置 |
|---|---|
| 扩展模块抛错拖垮主插件 | 加载与调用都包 try/catch，单个模块失败只 warn 并标红，不影响路由 |
| 压缩模块与内置压缩共存 | 注册前检测 `ctx.compaction` 是否已被占用；被占用则**主动放弃并 warn**，不硬抢 |
| 反代路径与宿主路由冲突 | 统一挂 `/_team/` 前缀下，注册前查重；冲突拒绝注册 |
| 扩展成为第二个"字段名漂移源" | 扩展的对外形状写进 `docs/02` §二（端点）与 `docs/03`（若有 UI），纳入 `check-contract` |
