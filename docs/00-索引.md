# 00 索引（先读这份，只要 30 秒）

> 这是 DSH 插件 `dsh-model-team` 的文档入口。**除本文件外只有 8 份文档**，每份只负责一件事。
> 你不需要读完所有文档——按下表找到你要做的事，只读那一份。

## 项目是什么

在 DSH 的模型列表里**只注册一个虚拟模型**；真实模型由插件按「session」映射改写后转发。
切换模型不在 DSH 的选择器里做，而在插件自己的群聊界面里做：平台账号 = 群、模型 = 群友、`@` = 切换本 session 目标。

## 三条铁律（违反任何一条，交付一律不算完成）

1. **契约唯一**：接口、字段名、事件、错误码只以 `02-契约.md` 为准。任何文档与契约冲突 → 契约胜，并提 issue 修文档。
2. **一手证据**：验收必须贴**你自己跑出来的输出**。「应该没问题」「本地 mock 通过」不算证据（历史事故：9 个前端 bug 里 6 个是真机才发现，本地 mock 全部"通过"）。
3. **不许猜**：契约里没写的，先提出来冻结，**不许按惯例先做一版**（历史事故：前端发 `driverId`、后端读 `driver`，加群恒失败）。

## 门禁命令（交付前必跑，输出要贴进汇报）

```bash
node scripts/check-contract.mjs      # 契约与代码一致性（端点表、字段名、DOM 钩子）
node build.cjs                       # 构建客户端产物
node --check lib/client.js           # 产物语法
node --test test/*.test.js           # 全部用例
node scripts/code-lines.mjs $(git ls-files '*.js' | grep -v '^lib/client.js')   # 代码行口径
```

期望：前四条全绿，第五条无单文件超 400 **代码行**（空行与纯注释不计）。

## 文档怎么写（写给维护者）

- 只写**当前有效**的结论与依据，不写讨论过程、不写「第 N 轮」「用户说」
- 一个事实只出现在一份文档里；其他地方只能引用编号（如「见契约 §3.2」）
- 状态性描述必须带核对日期；数字必须能回答「什么时候用什么命令核的」
