# 11 反代与本地网关设计稿

> 状态：**未实现**。交付形态见 `09`（本插件的子模块，`kind: proxy` / `kind: gateway`）。
> 参考实现：`dsh-providers-hub`（`src/openai-gateway/`、`src/opencode-proxy.ts`、`src/gemini-proxy.ts`），本文的学习点都标了出处。

## 一、两者方向相反，别混在一起

| | 本地网关 | 反代 |
|---|---|---|
| 方向 | **入站**：外面的人/工具访问我们 | **出站**：我们去访问上游 |
| 解决的问题 | 让本插件能被别的客户端当 OpenAI 端点用 | 让我们的请求能穿过代理/落地到特定出口 |
| 暴露面 | HTTP 路由 + 鉴权 | 不发新路由，改的是 `fetch` 的 dispatcher |
| 参考 | `src/openai-gateway/` | `src/opencode-proxy.ts` |

## 二、本地网关

### 2.1 路由面（照参考实现收敛，不贪多）

| 方法 | 路径 | 说明 |
|---|---|---|
| GET | `/v1/models` | 返回我们注册的模型清单（本插件只有一个虚拟模型 + 可选真实模型别名） |
| POST | `/v1/chat/completions` | 主入口；本插件已有，缺的是鉴权与对外开关 |
| POST | `/v1/responses` | 参考实现也提供；**可选**，先不做 |

### 2.2 鉴权：key 的形态要能机械判定

参考实现（`src/openai-gateway/auth.ts`）三个要点：

1. **密钥形态定长**：`randomBytes(32).toString('base64url')` → 恒 43 位、字符集 `[A-Za-z0-9_-]`。定长的意义是能机械区分「文件损坏」与「用户自己换过」，而不是笼统报「密钥无效」
2. **两处来源**：env 优先（`DSH_OPENAI_GATEWAY_API_KEY`），文件兜底（数据根下 `api-key`），并在设置页显示**来源与路径**（`ApiKeySource`），方便用户备份
3. **日志绝不打印密钥本体**；写文件用 `mkdir + 临时文件 + rename` 原子落盘

### 2.3 运行期开关：期望状态 + 收敛

参考实现把「设置页开关」当**期望状态**存起来，由 `runtime.ts` 收敛到实际状态（`setGatewayDesiredEnabled` / `registerGatewayFactory` / `applyGatewayDesiredState`）。
好处：开关切换不需要重启；坏处：**工厂会在运行期被调用**，同步异常必须就地消化（见下条）。

### 2.4 铁律：网关任何失败都不许抛到 `apply()`

参考实现的原注释写得很直接：`mountOpenAiGateway()` **绝不能抛异常**，否则整个插件加载失败，12 个 provider 的登录/积分/模型目录全不可用——网关只是**旁路功能**。

而且**必须同时保护同步创建与异步收敛**：`createOpenAiGateway()` 会同步执行配置解析（端口非法即抛）与密钥加载（home 不可写即抛），只在 `start()` 外面包 try/catch 接不住——「这正是初版只给异步加 catch 时留下的缺陷」。

### 2.5 不预检拦截，只翻译错误

参考实现（`src/openai-gateway/model-errors.ts`）：隐藏的模型不该出现在 `/v1/models`，但**显式请求仍要放行**（远端可能新上线、或用户只是不想在列表里看到）。
所以网关**不做白名单预检**，只把上游的「模型不存在」翻译成客户端能懂的错。

对我们的含义：不要在网关层再判断「这个模型我们认不认识」，直接交给路由与上游，只做错误翻译。

### 2.6 附件（可选，后置）

参考实现把客户端传来的 base64 图片落成 DSH 附件，用的是 `ctx.get('attachments')` 而非 `inject`——**附件服务缺失时文本能力不受影响**，只在收到图片时明确报错，不静默丢图。

## 三、反代

参考实现的核心是「每账号一个 undici Dispatcher」，四条硬注意事项：

1. **HTTP(S) 代理必须传 `clientFactory` + `pipelining: 0`**
   默认的 keep-alive 连接池会被 Clash 类代理**静默关闭空闲 CONNECT 隧道**，表现为请求挂死。参考实现注释记录实测：默认配置 2/10 成功，加这两个参数后 10/10。
2. **SOCKS5 自己实现最小 CONNECT**（RFC 1928 握手 + RFC 1929 认证）因为 Node 生态没有给 undici 用的纯 JS SOCKS 栈；但**不自写加密协议栈**（边界明确）。
3. **作用域只在本次请求**：`fetch(url, { dispatcher })` 逐请求传入，**不动全局 dispatcher**。参考实现注释记着教训：两个插件抢全局槽位会互相短路整个路由层。
4. **统一出口函数**（`proxyFetch`），禁止各处自己写 `fetch(url, { dispatcher: ... })`——绕过封装就是缺陷来源。

对我们的含义：代理配置应挂在「群」上（每个平台账号可走不同出口），并且**必须支持直连**（无代理时行为不变）。

## 四、参考学习点汇总

| 学习点 | 出处 |
|---|---|
| 网关失败必须降级为日志，不许抛到 apply | `openai-gateway/index.ts` 的 `mountOpenAiGateway` 注释 |
| 同步创建与异步收敛都要包 | 同上（原注释点名「初版缺陷」） |
| key 定长形态 + 双来源 + 日志不打值 + 原子写 | `openai-gateway/auth.ts` |
| 运行期开关用「期望状态 + 工厂收敛」 | `openai-gateway/runtime.ts` 的 4 个导出 |
| 不预检拦截模型，只翻译上游错误 | `openai-gateway/model-errors.ts` 文件头 |
| 附件用 `ctx.get` 不用 `inject`（缺失降级） | `openai-gateway/index.ts` 的 `makeGatewayAttachmentBridge` |
| 代理池：`clientFactory` + `pipelining: 0` | `opencode-proxy.ts` 文件头 |
| 代理作用域只在本次请求，不抢全局 | 同上（「R1 教训」） |
| 统一 `proxyFetch` 出口 | 同上（「缺陷 IKK4BY」） |

## 五、与现有代码的关系（不破坏）

- 本插件**已有** `POST /v1/chat/completions`，由 `http.externalOpenAiCompat` 开关控制，默认关。网关子模块 = 把它打开 + 补 `/v1/models` + 加鉴权，**不重写转发逻辑**
- 反代对现有链路是**透明新增**：群配置加可选的 proxy 字段，`stream` 里取 `proxyFetch`；没配代理时走原生 `fetch`，行为逐字节不变
- 两者都按 `09` 的子模块方式加载（`kind: 'gateway'` / `kind: 'proxy'`），失败只标记不可用，不影响路由主功能

## 六、MVP 顺序与验收

1. **反代**（更小、更急需）：群级 proxy 配置 → `proxyFetch` → HTTP(S) 代理可用，直连行为不变
   验收：配了代理的群请求成功；没配的群仍直连；代理不可达时报错明确、不挂死
2. **本地网关鉴权**：key 生成/读取 + Bearer 校验 + 401 语义
   验收：无 key 请求 401；错误 key 401；正确 key 正常返回；密钥不出现在日志
3. **网关 `/v1/models`**：与 `/_team/meta`、`/v1/models`（内部）保持同一口径
   验收：三处模型清单一致（可写一个断言脚本比对）

## 七、风险

| 风险 | 处置 |
|---|---|
| 网关抛错拖垮插件加载 | 见 §2.4：所有入口包 try/catch，失败只 warn，不向上抛 |
| 密钥泄漏进日志/仓库 | 只打来源与路径，不打值；数据根已 gitignore |
| 代理抢全局 dispatcher 与其他插件冲突 | 只逐请求传，永不设置全局 |
| 网关与 `externalOpenAiCompat` 语义重叠 | 明确：该开关是「是否对外」，网关子模块是「对外时怎么鉴权」，二者叠加判断 |
