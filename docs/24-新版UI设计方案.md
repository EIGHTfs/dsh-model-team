## 一、目标与边界

### 1.1 一句话目标

用一个可独立编写的 TSX 主题，把「群聊式多平台模型管理」做成**三层信息密度**的界面，并且**不依赖真实登录态**就能在 10 秒内看到完整界面。

### 1.2 三条硬约束（贯穿全文）

| # | 约束 | 落点 |
|---|---|---|
| C-1 | **副标题由提供方决定** | `summary` 原样渲染，通用层不加默认文案、不做变量替换（`02` §3.9） |
| C-2 | **只读契约，不改字段语义** | 需要改契约的地方单独列在 §八，等你决策 |
| C-3 | **本次不动 `src/`、`lib/client.js`、`ui/`** | 只新增 `docs/`，其余文件零改动 |

### 1.3 不做什么

- 不实现主题代码、不装依赖、不改构建脚本；
- 不修已知缺陷（`G-06`、`G-08`、`群 request.maxTokens 无入口` 等），只在设计里预留位置；
- 不替换现有界面：新旧并存，靠配置切换（`22` §7.1）。

## 二、现状核对（实测）

### 2.1 预览链路已经可用

| 项 | 实测结果 | 命令 |
|---|---|---|
| 假后端起得来 | `200` | `node scripts/mock-team-server.mjs --port 8766` |
| 预览页可打开 | `200` | `http://127.0.0.1:8766/ui/index.html` |
| 群列表有数据 | 2 个群，`summary` 是**已渲染成品**（`限速 60/min · 余 12 credit`） | `curl -s .../\_team/groups` |
| 页面实际渲染 | 三 tab、群列表两项、右侧悬浮球（截图见 §六.1） | 浏览器访问 |

**关键发现**：`ui/index.html` **不经过 `__ModuleLoader__`**，它是逐个 `<script src>` 直接加载源分片（`ui/index.html:104-136`）。
这意味着：

- 现有预览 = **真实 client 源码**（不是 mock 层），数据来自 `mock-team-server`；
- 但它**不是宿主加载路径**（宿主走 `lib/client.js` 的 ModuleLoader 工厂）。

这条差异直接决定验证方案要分两条路（§六）。

### 2.3 契约里**已存在但 UI 未覆盖**的字段

这是本次设计要补的核心内容（读码 + 契约比对得出，非推测）：

| 字段 / 错误码 | 契约位置 | 现有 UI | 缺口 |
|---|---|---|---|
| `summary` 空字符串 | `02` §3.9 缺省行 | 渲染成副标题区空白 | 需要**整行不占位**，不能留空 div |

## 三、界面结构设计

### 3.1 信息架构（三层）

```
┌─ L0 常驻层（全局唯一，始终可达）────────────────────┐
│  悬浮球：当前目标徽标（平台头像/首字母 + 目标名）      │
│  点击 → 面板；可拖动；整块留在视口内                  │
└──────────────────────────────────────────────────┘
┌─ L1 面板层（点球展开，轻量概览）────────────────────┐
│  当前群聊 / 会话 / 当前目标 / 速率 / 全局量           │
│  [进入群聊界面]                                      │
└──────────────────────────────────────────────────┘
┌─ L2 主窗口（重操作）───────────────────────────────┐
│  消息（群列表 → 群聊） / 通讯录 / 我                  │
└──────────────────────────────────────────────────┘
```

**为什么保持三层**：L0 必须常驻（`INV-14` 决定了显隐），L1 承担「一眼看状态」，L2 承担「可能要滚很久的操作」。三层各有明确职责，不做合并。

### 3.2 页面清单

| ID | 页面 | 进入方式 | 主要数据 |
|---|---|---|---|
| `P0` | 悬浮球（收起态） | 常驻 | `effectiveTarget`、接活平台 |
| `P1` | 悬浮面板 | 点球 | 同上 + `sessionTitle`、`rate`、`global` |
| `P2` | 消息列表（群列表） | L1「进入群聊界面」/ 底边栏 | `groups[]` |
| `P3` | 群聊 | 点群列表项 | `messages[]`、`models[]`、`modelsStatus` |
| `P4` | 加群 | 消息列表「＋加群」 | `platforms[]`、`drivers[]`、`authSchema` |
| `P5` | 通讯录 | 底边栏 | `friendGroups[]`、`groups[]` |
| `P6` | 我（数据库） | 底边栏 | `groups[]`、导入导出 |

### 3.3 层级与导航规则

| 规则 | 内容 | 依据 |
|---|---|---|
| N-1 | 底边栏三 tab 是**唯一视图入口**，顺序固定：消息 / 通讯录 / 我 | `03` §5.2 条款 6、`INV-13` |
| N-2 | 顶栏只放：团队标识 + 当前视图名 + `× 收起` | `03` 条款 8 |
| N-3 | `P3` / `P4` 属于「消息」tab 的子视图，进入后底边栏仍可见 | `03` 条款 6 |
| N-4 | 从 `P3` 返回 = 回 `P2`；从 `P4` 返回 = 回 `P2` | `03` §5.5 条款 18 |
| N-5 | `P1` 的「进入群聊界面」落点是 `P2`（不是上次停留的 `P3`） | 现有 `dock.js` 行为 |

```
│ ③ 模型目录  [获取可用模型]             │
```

**必须遵守 `17` 的硬禁止项**（逐条）：

| # | 约束 | 在结构里的体现 |
|---|---|---|
| 1 | 不许点第二次才能开授权 | 「登录」按钮一次点击即开窗 |
| 2 | 不许整页重建 | 账号区独立容器，轮询只更新它 |
| 3 | 不许丢输入 | 平台/名称/地址在轮询期间保持 |
| 4 | 界面不出现「导入」 | 结构里无导入入口 |
| 5 | 不出现命令行 | 所有失败文案为人话 |

| 7 | 不带内部术语 | 显示 `Qoder`，无「（反代）」 |

#### P5 通讯录 / P6 我

保持 `03` §5.8 与现有结构，本次不改。**唯一调整**：P6「已连接的平台账号」列表同样遵守「`summary` 为空不渲染副标题」。

## 五、TSX 主题如何接入

### 5.1 主题文件形态（与 `22` 一致）

```
ui/themes/default.tsx     # 单文件：结构 + 组合 + 样式字符串
```

```tsx
export default defineTheme({
  meta: { id: 'default', name: '默认', contractVersion: 1 },
  styles: `[data-theme-root="default"] { … }`,
  Root: () => <Shell />,
});
```

### 5.2 界面结构在 TSX 里怎么表达（对应 §三）

| 结构 | TSX 写法 |
|---|---|
| 三层（L0/L1/L2） | `Root` 里三个并列组件，L0/L1 用 `position: fixed` |
| 三 tab | `<TabBar>`，`useView()` 决定选中 |
| 列表项副标题 | `{group.summary && <div className="sub">{group.summary}</div>}` ← **C-1 的代码级落点** |
| 请求卡片 | `<RequestRow row={row} expanded={…} />`，展开态条件渲染 `row.claimedReason` |
| 群友数三态 | `modelsStatus === 'loading' ? '—' : modelsStatus === 'error' ? '加载失败' : models.length` |

### 5.3 数据接入（SDK，`22` §五）

| 界面 | hook | 来源 |
|---|---|---|
| 群列表 | `useGroups()` | store `groups` |
| 群聊 | `useChat(groupId)` | store `messages` / `models` / `modelsStatus` |
| 目标 | `useTarget()` | store `effectiveTarget` / `targetSource` |
| 会话 | `useSession()` | store `sessionId` / `sessionTitle` |
| 统计 | `useStats()` | store `rate` / `global` |
| 动作 | `actions.openView/switchTarget/sendMessage/toggleRow` | 只走 `dispatch` |

**约束**：主题不 `fetch`、不读 `localStorage`、不改 `state`（`22` §6.4）。

### 5.4 与现有界面的切换

```jsonc
// config/config.json
{ "theme": { "source": "ui/themes/default.tsx" } }   // TSX 路径
{ "theme": { "html": "ui/index.html", "styles": ["ui/app.css"] } }  // legacy（现状）
```

两者**不得同时配置**（`22` §7.1 构建失败）。本次不动任何配置。

## 六、可快速验证（核心交付）

### 6.0 一句话

> `node scripts/mock-team-server.mjs --port 8766` + 打开 `http://127.0.0.1:8766/ui/index.html` = **不登录、不装依赖、10 秒看到完整界面**。

**已实测打通**（§2.1），无需真实账号。

### 6.1 基线证据（本次实测）

现有界面渲染结果（`mock-team-server` + `ui/index.html`，2 个群，副标题为后端成品）：

- 截图路径（本机，不入库）：`<Downloads>/ui-baseline.jpeg`
- 页面文本实测包含：`限速 60/min · 余 12 credit`、`5h 12/60 · 余额 $3.2`、三 tab `消息/通讯录/我`

这条证据的作用：**新主题必须与它逐项对齐**（§6.3 的 E 系列）。

### 6.2 两条验证路径

| 路径 | 验什么 | 命令 | 不验什么 |
|---|---|---|---|
| **V-A 预览路径**（快） | 真实 client 源码 + 真实渲染 | 见 §6.3 | 宿主加载路径、INV-14 显隐 |
| **V-B 宿主路径**（真） | ModuleLoader 工厂 + slot 注入 | `minihost start plugin=<仓库>` + `preview serve` | 依赖真实登录态的流程（反代登录） |

**取舍**：日常迭代用 V-A；合并前至少走一次 V-B。

> V-B 的已知限制（`06` G-23）：预览垫片无 `props.useProjection` → 悬浮球按 INV-14 判「不可知」而隐藏。所以**球显隐只能在 V-B 真宿主验证**，V-A 只看面板本体。

### 6.3 V-A 具体步骤（可直接复制）


## 九、风险与回退

### 9.1 风险

| # | 风险 | 可能性 | 影响 | 缓解 |
|---|---|---|---|---|
| K-1 | 复刻时漏掉交互语义（焦点/滚动/拖动） | **高** | 高：`F-01`/`F-02`/`F-05`/`G-dock` 复发 | M2~M5 每阶段对照 `06` 已修表反查 |
| K-2 | `summary` 空值规则没落地 | 中 | 中：列表空行抖动 | U-2 断言钉死 |
| K-3 | 通用层偷偷加默认文案 | 中 | 中：违反 C-1，新平台无法表达状态 | U-1 + U-3 断言；code review 检查 |
| K-4 | 预览路径（V-A）与宿主路径（V-B）行为不一致 | 中 | 中：本地绿、真机坏 | 合并前必须走一次 V-B |
| K-5 | 球显隐在 V-A 无法验证 → 误判「已验收」 | 高 | 中 | 文档明确写「仅 V-B 可验」，禁止用 V-A 结论替代 |
| K-6 | 主题内联第三方库导致产物膨胀 | 低 | 中 | `22` §14.1 B-4 断言 |

### 9.2 回退方式（逐层）

| 回退点 | 操作 | 影响面 |
|---|---|---|
| **R-A 配置回退** | 删掉 `config.json` 里的 `theme.source` | 立刻回到 legacy 界面，零代码改动 |
| **R-B 构建回退** | `git revert` 主题相关提交 | 产物回到旧版 |
| **R-C 门禁回退** | 移除 `check-ui-contract.mjs` 的门禁挂载 | 不影响运行时 |
| **R-D 部署回退** | 同步旧版 `lib/client.js` 到 profile + 重启宿主 | 需要重启授权（`dsh-restart-gate`） |

**关键设计**：因为主题是**配置切换**而非替换，**任何阶段都能一键回到现状**（R-A）。这是本方案最重要的可回退性保证。

### 9.3 不引入的不可回退项

| 不做 | 理由 |
|---|---|
| 删除 legacy 渲染代码 | 回退需要它；双轨期保留 |
| 改动 `lib/client.js` 的分片顺序 | 一旦错乱，回退要动构建脚本 |
| 给 `summary` 加前端兜底文案 | 违反 C-1，且会造成「看起来修好了但语义错了」 |
