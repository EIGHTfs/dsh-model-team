# 23 出站契约与优化计划（权威）

> 定位：**这份是权威计划**，不是讨论稿。凡与本文冲突的口头结论一律以本文为准。
> 现状：两条已知偏差（UA 被宿主覆盖、max_tokens 边界判断）都属**优化项**，不阻塞使用；
> 但必须在修完前一直挂在这里，防止再被遗忘或被重新误判成「重构弄丢了功能」。

---

## 一、根因结论（代码分析，非测试推断）

| 事实 | 证据 |
|---|---|
| 我们的代码里**没有** `deepseek-harness` 这个 UA 字面量 | `src/`、`lib/client-parts/`、`ui/`、`config/` 全量搜索为空 |
| 转发驱动**确实**设置了自己的 UA | `src/gateway/drivers/openai-compatible.js:201-204` 的 `requestHeaders` 含 `'user-agent': DEFAULT_USER_AGENT`；chat 与 models 两条路径都用它 |
| 适配器与 v0.3.0 **逐字节相同** | `git diff v0.3.0 -- src/plugin/adapter/` 为空 |
| 结论 | 代码没变、值没丢；**变的是执行环境**——请求经 `globalThis.fetch` 发出，宿主进程的包装层最后写 UA，覆盖了我们的头 |

`max_tokens` 那条同源但不同因：解析器能认出「max_tokens 不能超过 65536」，问题在边界判断
（`src/plugin/adapter/attempt-limits.js:54`）：当请求里的 `max_tokens` **恰好等于**学到的上限时，
被判为「不比上限大 → 不重试」，于是 400 原样抛给用户。

## 二、出站契约（新增条款，进 `12` 工程约定）

> **出站请求不得依赖宿主可能包装的全局设施。**

| 依赖 | 允许 | 不允许 |
|---|---|---|
| HTTP 客户端 | 自己持有（`node:https` / 自维护客户端） | 默认使用 `globalThis.fetch` 而不校验其 UA/头是否被改写 |
| 时钟 / 随机 / ID | 通过依赖注入传入并可在测试里替换 | 直接读全局并假定行为固定 |
| 环境变量 | 只用于部署差异的单值 | 承载结构性配置（见 `12` 配置承载规范） |

判据：**任何「上层可能替换其实现」的设施，都必须经依赖注入，且契约里写清它的行为假设。**
违反表现：代码不变、行为变；日志里看到的头与代码里写的不一致。

## 三、优化项（按此顺序做，做完逐条划掉）

### O-1 转发驱动改用自己的 HTTP 客户端

- 目标：`src/gateway/drivers/openai-compatible.js` 的两处发送（JSON 请求、SSE 流）不再经 `fetchImpl`
- 做法：参照反代已有的自维护客户端（`src/reverse/platforms/qoder/http-client.js`）写一个通用版，
  放到 `src/gateway/transport/upstream-client.js`（**中立层，不得 import `reverse/**`**）
- 要求：超时、取消信号、SSE 增量读取、非 2xx 错误收敛，行为与现有 `fetch` 路径**逐项对齐**
- 验收：真机对上游抓到的 UA 必须是 `dsh-model-team/<version>`；流式与非流式都要验

### O-2 `max_tokens` 边界判断修正

- 目标：`attempt-limits.js` 的重试条件从「大于」改为「大于等于」
- 附带：撞到上限时打一条结构化日志（`group` / `model` / `requested` / `learned` / `retried`），
  以后不用再靠推测判断「到底学没学到」
- 验收：把某个群的上限故意配高，第一次请求应看到 400 → 学到 → 自动重发成功，日志里两个值都在

### O-3 参考项目作为设计输入（纪律）

- 可学习的参考项目：`工作区/_refs/`（如 `proxy-hub`、`qoder2api-hub`）与 `工作区/dsh-providers-hub`
- 用法：**先读它们的实现再决定自己的做法**；转述时必须给「文件:行号」，不接受「大致是这样」
- 禁止：把参考项目的代码整段搬进来（许可与维护风险），只允许学思路与参数

### O-4 `max_tokens` 初值与上限来源（决策：暂不做）

现状（代码事实）：
- 插件**没有自带默认值**；初值来自宿主 `options.maxTokens`（DSH 模型设置里的「最大输出 token 数」），群配置 `request.maxTokens` 可覆盖
- 上游是否**能直接取上限**取决于平台：部分平台 `/models` 返回 `max_completion_tokens` / `context_length`，取到就不必撞 400；不返回的只能"撞到再学"
- 学到的 `effective` 会当天花板，所以一次撞到 65535 后，即使人工配置更大也会被压回 65535

三个候选优化（**本轮全部不做**，记录备查）：
| 编号 | 内容 | 不做的影响 |
|---|---|---|
| A | 插件侧给可配置默认值 `defaults.maxTokens` | 行为依赖"谁在宿主界面填过" |
| B | 从 `/models` 解析上限作为初始天花板 | 每进程至少多一次 400 |
| C | 人工预设可高于学习值 | 支持大输出的模型可能被历史学习值压住 |

**决定**：保持现状（撞到再学、学习值当天花板、初值取宿主/群配置）。原因：改动都涉及 `capMaxTokens` 语义，当前无实际阻塞案例。

## 六、定时器审计（按「能事件驱动就别用超时兜底」）

判据来自 skill `<DSH_HOME>/skills/event-driven-no-timeout-fallback.md`：**产品代码禁止用超时保证流程继续；超时只做测试探针；外部 I/O 超时属于产品语义，必须显式建模。**

| 位置 | 用途 | 判定 | 处置 |
|---|---|---|---|
| `ui/js/store/persist.js:41` | 持久化写去抖 | 合并写，不推进流程 | ✅ 保留 |
| `ui/js/store/groups.js:181` / `ui/js/interaction/session-bridge.js:197` | 失败重试的调度器（可注入） | 外部 I/O 失败重试，失败态已显式建模（degraded/隐藏 + 错误出口） | ✅ 保留 |
| `ui/js/interaction/reverse-login.js:84`、`ui/themes/tim.tsx` 登录轮询 | 设备码登录轮询 | 协议本身只能轮询（无回调事件） | ✅ 保留，注释写明理由 |
| `lib/client-parts/foundation/api.js:31/59` | 请求超时 abort | I/O 语义（对端可能不来） | ✅ 保留 |
| `lib/client-parts/theme-epilogue.js` | 「store 就绪通知没来」告警 | 仍是**对事件设超时** | ❌ **已删除**：改为事件必达（app.js 装配后同步调钩子；主题晚挂直接读 `__teamStore`） |
| `src/gateway/routes/stream.js:39` | SSE 心跳 | 保活语义（防代理断连） | ✅ 保留 |
| `src/reverse/platforms/qoder/catalog.js:86` | 目录拉取超时 | I/O 语义 | ✅ 保留 |
| `src/reverse/driver.js:92` | 同账号请求间隔 ≥1s | 协议节流（平台要求） | ✅ 保留 |
| `ui/js/view/admin.js:255` | 下载后延迟回收 blob URL | 浏览器下载起跑时序，立即回收会断下载 | ✅ 保留（平台行为） |
| `ui/js/app.js:40` | toast 自动消失 | UI 动画时长 | ✅ 保留 |
| **`ui/themes/tim.tsx` 登录轮询的 `catch`** | **错误后无限静默重试** | ❌ **兜底**：把"事件永不到来"掩盖成"慢一点" | **已修**：连续 3 次失败 → 明确失败态 + 显示原因，用户可重试 |

**首屏加载同样是「等事件」而非「等超时」**（用户实测：重启后群列表报超时，手点重试秒恢复）：
- 服务端 `GET /_team/stream` 连上即发 `event: ready`（路由已就绪 = 数据可取）
- 前端收到 `ready` 才拉首屏；`ui/js/store/groups.js` 的默认重试档已清空（`DEFAULT_GROUP_RETRY_DELAYS_MS = []`）
- 结论：不再存在"插件没准备好、前端靠超时重试"的路径

**结论**：13 处定时器中 2 处属兜底（`theme-epilogue` 告警、登录轮询无限重试），均已修；其余 11 处均可回答「它防的是哪个真实 I/O/协议/动画语义」。
新增定时器的门禁要求：PR 必须写明「它防的是哪个事件不来、该事件若永不来用户看到什么」。
