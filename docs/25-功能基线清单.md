# 25 功能基线清单（能力体检）

> 目的：**一次跑完，立刻知道哪些能力没了**，不再靠用户一个个发现。
> 工具：`npm run smoke -- --base <地址> --token <dsh_token>`（或 `node scripts/smoke-capabilities.mjs …`）
> 输出：每项「期望 / 实际」，失败即非零退出。
> **边界**：本文是**工具使用说明 + 清单**，不是契约；能力定义本身在 `02`/`03`。

## 一、为什么有这个清单

本项目多次出现「重构后功能静默失效」：登录不能发起、账号列表空、模型列表空、消息不刷新、排序乱。
它们的共同点是——**没有任何一处会主动告诉我们"这项能力坏了"**。门禁只覆盖了静态结构与单元行为，
覆盖不到"这个接口在这个部署上还通不通"。

所以基线清单 + 冒烟脚本是必需的：它把「能力是否还在」变成一条命令的结论。

## 二、清单（脚本逐条实现）

| # | 能力 | 期望 | 对应契约 |
|---|---|---|---|
| 1 | 元信息 `GET /_team/meta` | 有 `virtualModel` 与 `providerIds` | `02` §3.8 |
| 2 | 群列表 `GET /_team/groups` | 数组，每项有 `id`/`name`/`driver` | `02` §3.1 |
| 3 | 驱动列表 `GET /_team/drivers` | 含账号型驱动，且带 `platformId` + `authKind` | `02` §3.4 |
| 4 | 平台预置 `GET /_team/platforms` | 200 且为数组 | `02` |
| 5 | 账号列表 `GET /_team/reverse/accounts?platform=` | 非空、含 `nickname`、**不含 token** | `02` §3.6 |
| 6 | 登录发起 `POST /_team/reverse/login/start` | 返回 `loginUrl` | `02` §3.7 + `05` |
| 7 | 全局统计 `GET /_team/stats/global` | 有 `totalRows` 与 `cacheHitPercent` | `02` §2.6 |
| 8 | 好友分组 `GET /_team/friend-groups` | 数组（可为空） | `02` |
| 9 | 事件流 `GET /_team/stream` | 连上即收到首帧（心跳/事件） | `02` 端点 35 |
| 10 | 群可用模型 `GET /_team/groups/:id/models` | 非空（反代群来自上游目录） | `02` |
| 11 | 会话目标 `GET /_team/session/:id/target` | 返回 `target` 字段（可为 null） | `02` |

## 三、使用方式

```bash
# 主实例
npm run smoke -- --base http://<本机IP>:30800 --token <dsh_token>

# 隔离实例（先在实例日志里取 token）
node scripts/smoke-capabilities.mjs --base http://127.0.0.1:3083 --token <token> --platform qoder
```

token 取法：`grep -o "token=[A-Za-z0-9_-]*" <实例日志> | tail -1`

## 四、判定纪律

- **失败项先看「实际」**：状态码/字段形状已经把差异说清楚，不要再去现象层逐个猜。
- 冒烟失败**不等于**功能代码坏了：先分辨是「部署副本落后」「凭据过期」「上游不可达」还是「代码缺陷」。
  例：`/reverse/accounts` 返回 404 = 路由没挂载（部署落后），不是账号不存在。
- 冒烟通过**也不等于**界面正常：界面层另有 `03` 的 U-1~U-7 判据。

## 五、与其它门禁的分工

| 工具 | 覆盖 | 不覆盖 |
|---|---|---|
| `gate-all`（11 道） | 静态结构、单元行为、部署一致性、文档引用 | 真实实例上接口是否通 |
| `smoke-capabilities`（本清单） | 真实实例的接口可用性与形状 | 界面渲染、交互链路 |
| `check-messages-order` | 真实数据的消息排序 | 渲染顺序 |

## 六、首次实测结论（2026-11-10）

| 实例 | 结果 | 备注 |
|---|---|---|
| 隔离实例 | 10/11 通过 | 唯一失败：群可用模型 502（上游目录不可达） |
| 主实例（同步前） | 9/11 通过 | `/reverse/accounts`、`/reverse/login/start` **404 = 路由未挂载（部署落后）** |
| 主实例（同步后） | 10/11 通过 | 同上两项恢复正常；账号 3 条、登录可发起 |
| 两实例共同失败 | 群可用模型 502 | 上游目录拉取失败，需单独查（凭据或网络） |
