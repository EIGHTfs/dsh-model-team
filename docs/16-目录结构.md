# 16 目录结构

> 唯一职责：**代码放在哪、为什么在那里**。
> 判据来源：`project-directory-layout`（执行类 skill）。本文只记录本项目**实际采用**的形状与偏离理由，不重复规范原文。
> 维护：结构变化时同步本文；`scripts/check-layout.mjs` 校验本文提到的路径是否都真实存在。

## 一、总原则

| 原则 | 具体要求 |
|---|---|
| 新人三秒能猜到 | 看目录名就知道该往哪加代码；猜不到就是名字没取好，不是新人笨 |
| 按领域分层，不按技术分层 | `gateway/session/` 而不是 `gateway/controllers/` + `gateway/services/` |
| 发现 > 发明 | 先把现状整理成能用的形状，不为了对齐某种标准去搬一遍 |
| 功能低耦合 | 目录按职责分开，功能间只经公共接口通信，不读取其他功能的内部状态或存储 |
| 插件低耦合 | 插件自己声明能力；model-team 动态发现、动态注册；不静态 import 具体插件实现（目标契约见 `06`，当前缺口见 `13`） |
| 不为了凑规范搬目录 | 搬动必须有职责或依赖边界理由；目录分离不等于插件化完成 |

## 二、顶层

```
dsh-model-team/
├── src/         服务端真 ESM 模块（Node 直接 import）
├── lib/         客户端拼接分片（build.cjs 按顺序拼成 lib/client.js）
├── ui/          设计源：样式、脚本分片、界面骨架、配图
├── test/        用例（node:test，零依赖）
├── scripts/     门禁与构建辅助（都不进产物）
├── docs/        本套文档
├── config/      平台预置
├── build.cjs    构建入口（唯一入口）
├── package.json
└── README.md
```

**`src/` 与 `lib/` 的分界是构建形态，不是职责**：`src/` 由 Node 直接加载（真模块、有 import/export），`lib/` 由 `build.cjs` 按数组顺序拼成一个文件（彼此共享作用域、**没有 import**）。这是本项目对 `project-directory-layout` §二「lib vs src 按构建形态二选一」的落地形式——两者并存，因为确实有两种构建形态，不是混乱。

## 三、`src/`（服务端）

```
src/plugin/            DSH 插件接线层（宿主只认这一层）
├── adapter/           LlmAdapter 实现：listModels / stream / resolveModel
├── context/           会话上下文：容量申报、目标解析、回落链
├── image/             图片能力：预取、三态门禁
├── index.js           插件入口（注册 adapter、路由、客户端槽位）
└── support.js         插件层共用小工具

**`package.json` 的 `files` 白名单语义（运行时 vs 构建期）**

| 目录 | 进 files | 原因 |
|---|---|---|
| `src/`、`config/`、`cordis.patch.yml`、`README.md` | ✅ | 服务端入口与预置配置 |
| `lib/client.js` | ✅ | 客户端产物，宿主只加载它（`exports["./client"]`） |
| `lib/shared/` | ✅ | 运行期按模块 id 动态 import（如 `rate.mjs`） |
| `assets/` | ✅ | 可选运行期资产（`assets/reverse/qoder/*.wasm`）；缺失时由 `<dataRoot>/reverse/...` 兜底 |
| `ui/`、`lib/client-parts/`、`scripts/`、`test/`、`docs/` | ❌ | **纯构建期/开发期输入**：`ui/js`、`ui/themes/*.tsx`、`lib/client-parts` 全部内联或编译进 `lib/client.js`，运行时不需要 |

│   ├── account-store.js   账号落盘（0600、原子写、按 user_id 判重、导入账号标 origin/refreshable）

├── errors.js          错误码与 GatewayError
├── logger.js          日志
├── gateway-deps.js    依赖装配（把 options 解析成完整 deps）

```

**反代的运行时数据文件**（不在仓库里，落在 `<dataRoot>` 下）：`reverse/<platformId>/<accountId>.json` 是凭据（0600），`reverse/<platformId>/<accountId>.state.json` 是**失败治理状态**（冷却窗口/计数，0600）。两者分开：凭据只存身份与 token，状态可随请求频繁改写，混一起会让每次改状态都重写凭据文件。

**反代对 gateway 的依赖方向**（当前形态，见 `06` 目标）：`reverse/**` 允许 import `gateway/logger`、`gateway/config/paths`、`gateway/drivers`、`gateway/errors` 这类**基础设施**；反过来 `gateway/**` 不得 import `reverse/**`（结构门禁只放行 `reverse/register.js` 一个入口）。

**根上那 5 个文件为什么不建目录**：它们被 `src/` 各处引用（`errors`/`logger`/`clock`/`gateway-deps`/`mapping`），是**全层共用的最小设施**。给它们建 `core/` 只是把「基础设施」换个更模糊的词，且会让 `import` 路径多一层无意义的跳跃。

**`support/` 这个目录不存在**：「support / utils / common / helper / misc」都是垃圾桶名，装进去的东西彼此无关。原 `support/` 的 8 个文件按真实消费者拆散：`event-sort` → `session/`，`query-params` → `transport/`，`stats` → `stats/`，其余四个（clock/errors/logger/gateway-deps）与 `mapping` 留在根。

## 四、`ui/`（客户端设计源）

> **目录正在换形态（`03` R-1/R-4/R-7）**：要删的只有 **legacy 视觉层** —— `ui/index.html`（骨架）、`ui/app.css`、`ui/css/**`（样式）。最终 `ui/` 里**一个 `.html` 都不留**。
> **`ui/js/**` 不删**：它是「UI 功能实现」（store / 动作派发 / 悬浮件拖动 / 列表规则 / @ 选择器），由生成器（`build.cjs`）内联进产物；主题只做视觉，不重写它（`03` §0.2）。

```
ui/
├── themes/        主题（**一个主题 = 一个 tsx 文件**，各自完整独立）
│   ├── classic.tsx    现有界面的 TSX 复刻（基线）
│   └── tim.tsx        TIM 风格 = `参考项目/1.html` 的逐段转译（见 `03` §5.5.2.1）
├── theme-sdk/     主题适配层（把 ui/js 的既有功能包成 hooks / 动作对象）
│   ├── contract.ts      ThemeDefinition + defineTheme
│   ├── store-bridge.ts  store → 可订阅快照（版本号）
│   ├── hooks.ts         useGroups / useChat / useTarget / useSession / useView
│   ├── actions.ts       薄包装：转发到既有 dispatch，不写业务规则
│   └── index.ts         统一出口
├── shots/         本地自检截图（不入库，见 .gitignore）
│
├── ── 以下为 legacy 视觉层，M7 删除 ──
├── css/           样式（按部件分文件，app.css 用 @import 汇总）
└── index.html     界面骨架（构建期抽 <body>）——**M7 删除**
```

> **`ui/js/**` 仍然在这里，属于功能实现，M7 不动**（它的分工见下文 §四之二）。

### 四之二、`ui/js/`（UI 功能实现，保留）

> 子目录清单（`check-layout` 按「目录名/」比对，故此处平铺一遍）： store/ 、 interaction/ 、 format/ 、 float/ 、 friend-group/ 、 view/

| 子目录 | 职责 | 谁用 |
|---|---|---|
| `ui/js/store/` | 唯一真相源：state / groups / chat / stats / session / dispatch / persist / events | 主题通过 `theme-sdk` 的 hooks 读；动作经 `dispatch` |
| `ui/js/interaction/` | 事件与状态桥（@ 选择器、发送、目标切换、会话槽位订阅、反代登录） | 主题的按钮/输入最终落到这里 |
| `ui/js/format/` | 纯函数：文本/时间格式化、速率、来源文案 | 主题直接复用 |
| `ui/js/float/` | 悬浮件：拖动与夹取几何、开合状态、目标来源 | 主题的球与面板复用它，**不要重写** |
| `ui/js/friend-group/` | 通讯录分组弹窗（规则 / 视图 / 接线三文件） | 分组编辑功能；渲染部分随 `view/` 退役，规则部分保留 |
| `ui/js/view/` | **HTML 字符串渲染层**（`render.js` / `admin.js` / `messages.js` / `model-catalog.js` / `reverse-account.js`） | ⚠️ 这一层被 TSX 取代后逐块退役；但 `admin.js` 等文件里的**动作逻辑**要先取出再用，不许连逻辑一起删 |

**判断一句话**：`view/` 是"把数据画成 HTML 字符串"，TSX 主题不需要它；`store/`、`interaction/`、`float/`、`format/` 是功能本身，主题必须复用。

**判据一句话**：改界面长什么样 → `themes/<id>.tsx`（单文件）；改点了会怎样 / 数字怎么算 → `ui/js/`（既有）；`theme-sdk/` 只允许做适配。

**新增主题的判据**：一个 `.tsx` 文件 + 在 `config.json` 里指 `theme.source` 就能用。**不许**再引入 `base/`、`skins/`、`slots` 之类的分层抽象——那是把"单文件"拆开了，`03` R-2 已明确回退过。

## 五、`lib/`（客户端拼接分片）

```
lib/
├── client-parts/
│   ├── dock.js        挂载与显隐
│   ├── apply.js       启动编排
│   └── foundation/    底层分片（按 build 顺序，顺序即依赖）
│       ├── api.js         后端接口封装
│       ├── api-errors.js  错误映射
│       ├── session.js     会话 id 解析
│       ├── styles.js      样式注入
│       ├── utils.js       通用小函数
│       └── z-layers.js    层级常量与 CSS 变量
├── shared/            **可拷贝复用的独立单元**（纯 JS、零依赖、无宿主耦合，拷到别的项目即可用）
│   ├── rate.mjs       速率公式（生成速度口径 + 跨行聚合）；服务端按声明动态加载它，客户端不存第二份
│   └── patch-host-pi-ai-export.mjs  给宿主包补 resolveProfiles 导出
└── client.js          构建产物（**勿手改、不入库**）：由 build.cjs 生成，已 gitignore；部署与 npm 发布都由构建产出
```

**这个目录不按领域分，因为它不是模块系统**：`build.cjs` 把这里的文件按数组顺序拼进一个文件，物理顺序 = 依赖顺序。因此：
- 不建更深的功能目录（顺序会变得难追踪）
- 改名要同步 `build.cjs` 的数组，且顺序不能错（有断言把关）
- `utils.js` 是垃圾桶名，但**不改名**：它在顺序链中，改名风险大于收益，在此注明即可

## 六、偏离规范的记录

| 规范要求 | 本项目做法 | 理由 |
|---|---|---|
| `lib/` 与 `src/` 二选一，同层混放要拆 | 两者并存 | 存在两种真实构建形态：Node 直接加载 vs 拼接成单文件 |
| 不建 `support/utils/common` 垃圾桶 | 已全部拆散 | 见第三节 |
| 目录深≤3 层 | 未超过 3 层 | 合规 |
| 根目录散落文件≤3 | 3 个（build.cjs / package.json / README.md） | 合规 |

## 七、新增代码该放哪

| 你要加的东西 | 放这里 |
|---|---|
| 核心端点 | `src/gateway/routes/` 对应领域文件 + 核心路由表；不能在这里列可选插件的业务路由 |
| 可选插件端点 / 驱动 / 认证 | 由插件自己的声明提供，model-team 动态发现后按公共契约注册；不得新增核心静态依赖，见 `06` |
| 新的业务领域（如分组、标签） | `src/gateway/<领域>/` |
| 客户端新视图 | `ui/js/view/` + 在 `ui/js/app.js` 接线 |
| 客户端新交互 | `ui/js/interaction/` |
| 客户端纯计算工具 | `ui/js/format/` |
| 底部基础分片（被多处依赖） | `lib/client-parts/foundation/`，**并同步 build.cjs 顺序** |
| 门禁脚本 | `scripts/`（不进产物） |
