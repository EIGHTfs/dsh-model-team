# 16 反代账号模式：目录与架构设计（G13b 前置）

> 定位：把「用真实账号走厂商私有接口」这条链路设计清楚再动手。本文只定**结构与边界**，不含实现。
> 试点平台：**Qoder 国内版**（`openapi.qoder.com.cn` + `gateway.qoder.com.cn`）。其它平台按同一形状复制。
> 参考实现（只取逻辑，不取架构）：`dsh-providers-hub@2.17.261106` 的部署副本。

## 一、目标与边界

| 项 | 内容 |
|---|---|
| 目标 | 群里能像普通平台一样**发对话、拿到流式回复**；账号可登录、可续期、可多账号轮换 |
| 试点范围 | 仅 Qoder 国内版一条链路跑通 |
| 明确不学 | 参考实现的**架构**（272 个平铺模块、每平台 8-10 个文件、auth 与 product/credits/catalog 互相依赖） |
| 明确不做 | 不做通用 OAuth 框架、不做积分/签到/活动、不做跨平台抽象层、不做 UI（先 API） |
| 合规 | 账号风险与厂商条款由使用者承担；本插件不内置任何绕过风控的手段，只做「像官方客户端那样正常请求」 |

## 二、从参考实现提取的逻辑事实（每条都带出处）

| # | 事实 | 出处 |
|---|---|---|
| 1 | **设备的身份头族必须齐全**：`Cosy-MachineToken` + `Cosy-MachineType` + `Cosy-ClientType`；缺 machine 头族时服务端**不下发活动/能力**（曾表现为「积分已领取」但实际没领） | `qoder-machine.js` 文件头（抓包 + 逐项消融定位） |
| 2 | **`machine_id` 必须随凭据持久化并原样回传**（续期载荷是 `{refresh_token, machine_id}`） | `qoder-auth.js` 文件头 |
| 3 | **登录是设备码 + PKCE + 轮询**：`redirect_uri = qoder-app://`，轮询 `/api/v1/deviceToken/poll`，**不起本地回调端口**；总超时 5 分钟、轮询间隔 1 秒 | `qoder-oauth.js`、`qoder.js` 常量 |
| 4 | 登录必须**两步**（先生成 URL，再打开）：浏览器只在点击后约 5 秒内允许 `window.open` | `qoder-oauth.js` 文件头 |
| 5 | **续期用统一调度器语义**：`RefreshScheduler` + 登出竞态保护 + 批量 `refreshAll(pool)` | `qoder-auth.js` 文件头 |
| 6 | **推理通道是加密链路**：CN 为 `gateway.qoder.com.cn`，路径 `/algo/api/v2/service/pro/sse/agent_chat_generation?Encode=1`，**请求体由 WASM 加密**；公开的 `/model/v1/chat/completions` 只认通用模型名，目录 key（`qfmodel`/`dmodel`）会报 `Unsupported model` | `qoder-adapter.js:11-12`、`qoder-catalog.js:36` |
| 7 | **响应是 SSE + 信封**：每帧 `{headers, body, statusCode}`，内层 `body` 是标准 OpenAI chunk 的 **JSON 字符串**（`body` 未加密，只剥信封） | `qoder-envelope.js` 文件头 |
| 8 | **国内版与国际版是两条独立可达性**：国际 `openapi.qoder.sh` 在本机被 SNI 阻断（TLS ClientHello 被丢，恒 10.7s 超时）；国内 `openapi.qoder.com.cn` 直连 160ms | `qoder-proxy.js`、`qoder-rpc.js` 文件头 |
| 9 | 单请求超时 30s | `qoder.js` 常量 |
| 10 | WASM 上下文是单例、必须显式释放（`try/finally`），否则堆只增不减 | `qoder-adapter.js:756-758` |

**结论**：这条链路的复杂度集中在三处——**设备身份头族**、**WASM 加密请求体**、**SSE 信封剥离**。登录与续期反而是标准设备码流程。

## 三、为什么不照抄参考实现的架构

| 它的做法 | 问题 | 我们怎么做 |
|---|---|---|
| 272 个模块全部平铺在 `lib/` | 找「某平台怎么登录」要翻 8 个文件 | 一个平台一个目录，目录内按职责分文件 |
| 每平台 `-auth / -oauth / -adapter / -messages / -credits / -product / -catalog / entry` | 8-10 个文件，其中 credits/product 我们根本不做 | 只保留 5 个必需文件 |
| `auth` 依赖 `product`（取端点），`adapter` 依赖 `catalog`（取模型） | 循环依赖、改一处牵连多平台 | 平台描述集中在 `index.js`，其余模块只读它 |
| WASM 与协议细节混在 adapter 里 | 加密逻辑无法单测 | 抽出 `crypto.js`，用 golden 向量单测 |

## 四、目录结构

```
src/gateway/reverse/            反代账号模式（与 drivers/ 平级，因为它不是「一个驱动」而是「一条账号链路」）
├── index.js                    ReversePlatform 注册表：platformId → 平台实现；启动时校验形状
├── types.js                    契约常量与形状校验（纯数据，无 IO）
├── account-store.js            凭据持久化：读写 <dataRoot>/reverse/<platformId>/<accountId>.json（0600）
├── account-pool.js             多账号：轮转游标、冷却、失败计数、健康度
├── login-session.js            设备码登录的**平台无关状态机**：start → poll → 完成/超时/取消
├── refresh.js                  续期调度：到期前续、失败退避、登出竞态保护
├── http-client.js              代理感知 fetcher：直连 / 出口代理 / 超时 / 错误归一
└── qoder/                      试点平台
    ├── index.js                平台描述：openApiBase、encryptedInferBase、端点表、能力位
    ├── oauth.js                设备码 + PKCE + 轮询（纯函数 + 一个 poll 循环）
    ├── headers.js              Cosy-* 头族、UA、machine token 生成与校验
    ├── crypto.js               WASM 加密请求体（含单例生命周期与 try/finally 释放）
    ├── envelope.js             SSE 信封剥离（纯函数）
    └── catalog.js              模型清单（目录 key ↔ 展示名）
```

**行数预算**：`index.js`/`types.js`/`envelope.js`/`catalog.js` ≤100；`oauth.js`/`headers.js`/`crypto.js`/`account-store.js` ≤200；`account-pool.js`/`refresh.js`/`login-session.js` ≤250。超 400 即视为职责没拆清（与全仓门禁同口径）。

## 五、架构分层

```
群(accessMode=reverse, driver=<platform>)
  ▼
drivers/ 里的 reverse 驱动（薄壳，只做「协议 ↔ 本插件消息形状」的转换）
  ▼
reverse/index.js  按 platformId 取平台实现
  ▼
┌───────────────────────── 共享层（平台无关）─────────────────────────┐
│ login-session  设备码状态机     account-store  凭据持久化            │
│ refresh        续期调度         account-pool   多账号轮转/冷却        │
│ http-client    代理/超时/错误归一                                    │
└──────────────────────────────────────────────────────────────────────┘
  ▼
qoder/  平台实现（只实现契约里的方法，不含调度与存储）
```

**平台契约（一个平台 = 一个目录，导出这些）**：

```js
export const id = 'qoder';
export const endpoints = { openApiBase, inferBase, deviceCode, deviceTokenPoll, refresh, usage };
export function createPlatform({ http, crypto, now }) {
  return {
    startDeviceLogin(),          // → { userCode, verificationUrl, intervalMs }
    pollDeviceLogin(session),    // → { status: 'pending'|'granted', credential? }
    refreshCredential(credential),// → 新 credential（含 machine_id 原样回传）
    buildHeaders(credential),    // → Cosy-* 头族 + UA
    encodeRequestBody(body),     // → 加密后的请求体（WASM）
    decodeStreamChunk(rawEvent), // → 标准 chunk（剥信封，纯函数）
    listModels(credential),
  };
}
```

**与现有体系的接缝**（不新增第二套概念）：

| 现有概念 | 反代怎么接 |
|---|---|
| `groups[].accessMode` | 已有 `official` / `reverse` 两值，直接用 `reverse` |
| `groups[].driver` | 新增驱动 id `qoder`，在 `drivers/` 注册；驱动内部调 `reverse/index.js` |
| 凭据 | 沿用「只存引用」：`auth.apiKeyRef = 'account:qoder/<accountId>'`，实体在 `account-store` |
| 请求行 / stats | 完全复用；`targetSource`、usage、latency 语义不变 |
| 导出/备份 | 沿用 v2 `credentialFiles` 机制，把 `reverse/` 下的账号文件纳入导出范围 |
| UI | 本轮不做；将来加「账号登录」入口时只调 `login-session` |

## 六、防封设计（只做「像官方客户端」，不做绕过）

| 措施 | 具体做法 | 依据 |
|---|---|---|
| 设备身份稳定 | `machine_id` 生成一次、与凭据同存、续期原样回传；**不每次请求重新生成** | 事实 1、2 |
| 头族齐全 | 每个请求都带 `Cosy-MachineToken` / `Cosy-MachineType` / `Cosy-ClientType`；缺一不可 | 事实 1 |
| UA 一致 | 用与官方客户端同形的 UA（不是 `node`），且**按平台可配**；改动需过单测 | 既有教训（UA 曾是 `node`） |
| 出口一致 | 国内版**不绕代理**（直连 160ms）；需要代理时装在 `http-client` 一处，按平台开关 | 事实 8 |
| 单账号串行 | 同一账号同时只跑一个请求（`account-pool` 加锁）；并发会显著提高风控命中 | 通用做法 |
| 失败分类 | 401 → 续期重试一次；429 → 该账号冷却 N 分钟；风控类错误码 → 拉黑一段时间并告警；其它 → 原样上报 | 与现有 `ERROR_CODES` 对齐 |
| 退避 | 续期失败按 1s/5s/30s 退避，最多 3 次，之后标记 `needs-login` | 事实 5 的调度语义 |
| 日志 | 只记账号 id 与状态，**绝不打 token / cookie / machine 明文** | 与备份导出口径一致 |

## 七、数据与安全

- 凭据文件：`<dataRoot>/reverse/<platformId>/<accountId>.json`，权限 `0600`；内容含 `refresh_token`、`access_token`、`expiresAt`、`machine_id`、`machine_type`。
- 写入原子化（临时文件 + rename）；损坏按「未登录」处理并提示重新登录。
- 导出备份：纳入现有 v2 `credentialFiles`，键为相对 dataRoot 的路径。
- 日志与错误文案永不包含 token；`limits.json` 那类学习型状态与账号无关，分开存。

## 八、风险

| 风险 | 说明 | 缓解 |
|---|---|---|
| 厂商接口变更 | 私有接口无契约，随时可能变 | 端点集中在 `qoder/index.js` 一处；变更只改一个文件 |
| 加密链路失效 | WASM 版本与厂商侧不同步会全挂 | 加密失败按「不可用」上报，绝不降级成明文请求（会更容易被风控） |
| 账号被封 | 无法完全避免 | 单账号串行 + 冷却 + 不做异常高频；文档写明风险由使用者承担 |
| 国际版不可达 | 本机 SNI 阻断 | 试点只做国内版；国际版需要代理时走 `http-client` 一处开关 |

## 九、里程碑

| 阶段 | 内容 | 判据 |
|---|---|---|
| M1 | 目录骨架 + `types.js` 契约 + `envelope.js`/`catalog.js`/`headers.js` 纯函数 + 单测 | 纯函数单测全绿，无网络 |
| M2 | 登录闭环：`login-session` + `qoder/oauth.js` + `account-store`（用 stub 上游模拟设备码与轮询） | 能在 stub 上走完「取码 → 轮询 → 落库」；超时/取消路径有断言 |
| M3 | 推理链路：`crypto.js`（WASM）+ `http-client` + 驱动薄壳，打通一次流式对话（stub 上游模拟加密端点与信封 SSE） | 客户端拿到标准 chunk；加密失败不降级 |
| M4 | `account-pool` + `refresh`：多账号轮转、冷却、续期 | 单账号串行有断言；401 续期一次；429 冷却 |

## 十、验收标准

- 每阶段：既有用例零改动（新行为用新增用例）；八道门禁全绿；`src/**` 改动跑 deploy parity。
- M3 起：请求行字段（usage / latency / ip / req-id）与 official 路径口径一致。
- 任何阶段：日志中搜不到 `refresh_token` / `access_token` / `machine` 明文（用 grep 自证）。

## 十一、本次不做

- UI 登录入口、二维码渲染（先 API）
- 积分/签到/活动（`/sash/api/v1/me/campaigns`）
- 其它平台（LobsterAI / CodeArts / astudio 等）——等 Qoder 跑通后按同一目录形状复制
- 通用 OAuth 框架与跨平台抽象（只在出现**第二个**平台时才抽公共层）
