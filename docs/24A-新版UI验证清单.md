## 〇、本次实测结论（先看这段）

在**现有界面**上实跑，V/D 两组共 13 条中 **12 条通过、1 条不满足**：

| 项 | 结果 |
|---|---|
| D-1 ~ D-4 数据契约 | ✅ 全部通过，`summary` 确为后端成品字符串 |

`00000000` 的来源：mock 会话 id 为 `session-00000000-…`，去掉 `session-` 前缀后取前 8 位正好是 `00000000`；且 mock 数据无 `sessionTitle`。
**这属于 mock 数据现象，不是代码缺陷**——但暴露了一个真实设计问题：**无标题时只显示 id 前 8 位，可读性极差**（`03` 条款 5 允许，但无法分辨是哪个会话）。已记入 §十 待决策。
